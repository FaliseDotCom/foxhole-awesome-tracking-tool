# Plan: map search and keeping the focal point on resize

Date: 7 October 2026. Status: done. Search is in `stores/search.js`, `stores/view.js`, `components/search.svelte`, and `assets/css/search.css`; the resize fix is in `panzoom.svelte`.

Two features:

1. A search field at the top of the screen that suggests places and structures as you type
   and moves the map to the chosen one.
2. When the window is resized (or a phone is rotated), the map point at the centre of the
   screen stays at the centre.

## What can be searched

| Kind | Source | Count | Shown as | Example |
| --- | --- | --- | --- | --- |
| Hex | `title` in `world_data.json` | 37 | name | Dead Lands |
| Area (major label) | keys of `areas`, with `x`/`y` | 325 | name | The Spine |
| Location (minor label) | `labels[].text`, with `x`/`y` | 452 | name | Biting Tarn |
| Structure | live map items from the world store | about 2,900 | type – location | Hospital – The Spine |

Places come from the static `world_data.json`. Structures come from the live data of the
selected shard, so their part of the index is rebuilt when a hex's data `version` changes
and is replaced when the shard changes.

A structure's **location** is the nearest named place in its hex: the closest major or minor
label by distance, falling back to the hex title. Its **type** is the name in `icons.js`
(`Hospital`, `Seaport`, `Town Base Tier 3`). The suggestion's second line adds the team and
hex, for example "Wardens · Dead Lands", so a structure can be told apart from one of the
same type nearby.

`x` and `y` in the data are fractions of the hex (0–1). The position on the map in pixels is
the hex's `grid.bounds( hex )` plus `x × 1024` and `y × 888`; a hex itself uses the centre of
its bounds.

Data quirks the index handles:

- Westgate and Godcrofts contain exact duplicate labels; deduplicate on hex + text + position.
- Hex titles have no apostrophes ("Callahans Passage") while labels do ("Callahan's Gate"),
  so matching ignores punctuation.
- The 16 hexes added since 2022 are not drawn yet, so their places and structures are not
  searchable until they are (see `2026-10-07-new-hexes.md`).

## Matching and ranking

- **Normalisation:** lower case, strip diacritics (`normalize( 'NFD' )`), drop apostrophes and
  other punctuation, collapse spaces. "callahans" matches "Callahan's Gate".
- **Several words:** the query is split into words and every word must match the start of a
  word somewhere in the entry's searchable text. For a place that text is its name; for a
  structure it is type + location + hex. So "hosp spine" finds "Hospital – The Spine", and
  "seaport dead" finds the seaports in Dead Lands.
- **Ranking**, for a query of at least 2 characters:
  1. the whole query matches the start of the name,
  2. every query word matches the start of a word in the name (rather than only in the
     location or hex part),
  3. every query word matches somewhere in the searchable text.

  Within a rank: places before structures (hex, area, location, structure), then shorter
  names, then alphabetical. At most 8 suggestions.
- **Many identical structures:** resource fields and mines repeat a lot ("Salvage Field –
  …"). They rank last among structures so towns and named places are not pushed out.

## Recent searches

The last 5 chosen entries are kept in `localStorage` (key `fatt-recent`, read and written in
`try`/`catch`), newest first and without duplicates. When the field gets focus while empty,
the suggestion list shows them under a "Recent" heading, and they work like any other
suggestion (arrow keys, Enter, click). Each has a small remove (×) button. Places are stored by kind + hex + name and resolved against the index again;
structures by type + location + hex, and dropped when that structure no longer exists.

## Interaction

This follows the usual map search pattern (Google Maps, OpenStreetMap):

- Suggestions appear while typing, from 2 characters.
- **Up/Down** move the highlight through the list; it wraps.
- **Enter** chooses the highlighted suggestion, or the first one when none is highlighted.
  With no suggestions, Enter does nothing.
- **Escape** closes the list; a second Escape clears the field and returns focus to the map.
- **Choosing** (Enter, click, or tap) moves the map to the result, closes the list, and puts the
  chosen name in the field, so you can see what you are looking at. A clear (×) button in the
  field empties it. Typing again starts a new search.
- **`/`** anywhere on the page focuses the field (common in web apps; the map has no other
  use for it).
- **Mouse and touch:** choose on `pointerdown` so the input's blur does not close the list
  first; tapping outside closes it.

### Map keys are off while typing

`panzoom.svelte` listens to `keyup` on `window` and pans on the arrow keys, WASD, and the
numpad, and zooms on `+` and `-`. While the search field (or any other form field) has focus,
these keys must do nothing: `onKeyUp` returns early when the event target is an `input`,
`textarea`, `select`, or content-editable element. Escape out of the field (or a tap on the
map) gives the keys back to the map.

## Moving the map

### View store: `src/stores/view.js`

The `panzoom` instance lives inside `panzoom.svelte`; search must not reach into it. A small
store carries view requests:

- `focus( { x, y, scale } )` publishes a request; `panzoom.svelte` subscribes, centres map
  point `x`/`y` on screen at `scale` with `smoothZoomAbs`, and clears the request.
- Target zoom: the chosen result must be fully in view, so the map zooms in or out from
  wherever it is:
  - hex: fit the whole hex on screen with a margin;
  - area: fit the area's outline (the bounding box of its polygon from
    `grid.getPolyArrays( hex )`) with a margin. A large area zooms out, a small one zooms in.
    Areas without an outline (some hexes have none yet) use 0.8, where region names show;
  - town, location, and structure: zoom in close, to 1.5, where icons and minor labels show.

  "Fit" uses the same calculation as the start-up fit in `panzoom.svelte` (`centerMap()`),
  applied to a box instead of the whole map, and is clamped to the zoom limits in
  `stores/zoom.js`. A town is the town base (town hall) structure, or the area label it
  belongs to when chosen as a place name.
- Highlight: publish the chosen entry for about 2 seconds so a marker layer can draw a pulsing
  ring at the point. The existing area flash only covers areas, so a small marker component
  works for every kind.

## Component: `src/components/search.svelte`

- **Placement:** top centre, between the logo (top left) and the shard picker (top right). On
  narrow screens it moves below the logo at full width minus margins, so nothing overlaps.
- **Markup:** the ARIA combobox pattern: `input role="combobox"` with `aria-expanded`,
  `aria-controls`, and `aria-activedescendant`; suggestions in a `role="listbox"` with
  `role="option"` items. Each suggestion shows the name on the first line and kind, team, and
  hex on a smaller second line. Structures show their icon in front.
- **State** lives in `src/stores/search.js`: `{ query, suggestions, active, recent }` with
  `setQuery( text )`, `move( step )`, `choose( entry )`, and `clear()`. The component only
  renders and dispatches (the `svelte` skill).
- **Styling:** new `assets/css/search.css`, loaded from `app.html`, using the variables in
  `vars.css` and the half-transparent white panel style of the logo and shard picker.

## Tests (`src/tests/`)

  the field.
- Type "callahans": both "Callahans Passage" and "Callahan's Gate" are suggested.
- Type "hosp" plus the name of a location that has a hospital: a "Hospital – …" suggestion.
- Typing "wasd" in the field does not move the map.
- Choose a place, reload, focus the empty field: it appears under "Recent".

## Keeping the focal point on resize — done

Before: `panzoom.svelte` had an empty `onResize()` and no resize listener, so after a resize
the map stayed anchored to the top-left corner, and the visible-hex calculation in
`stores/visible.js` (which uses the window size) was not refreshed.

Now `panzoom.svelte` listens to `resize` on `window` (debounced), works out which map point
was at the centre of the old viewport, and moves the map so that point is at the centre of the
new one, at the same zoom. It then runs `onPanzoomUpdate()`, which refreshes the zoom store,
the visible rows and columns, and the saved view. A Playwright test resizes the viewport and
checks the centre point stays put.
