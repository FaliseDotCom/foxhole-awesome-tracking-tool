# Plan: add the new hexes and refresh the existing ones

Date: 7 October 2026. Status: done, see "Result" at the end.

F.A.T.T. draws the 37 hexes that existed in November 2022. The War API now lists 53. The
backend already fetches data for all of them; what is missing is everything the frontend
draws from local files.

## What a hex needs

| Part | Where it lives | Source |
| --- | --- | --- |
| Grid position (`col`, `row`) | `.app/src/stores/world_data.json` | Not in the War API; see "Grid positions" |
| Region id, title | `world_data.json` (`id`, `title`) | War API `maps/{hex}/static` (`regionId`); title from the hex name |
| Region names and label positions | `world_data.json` (`areas[name].x/y`) | War API static `mapTextItems` with `mapMarkerType: "Major"` |
| Minor labels | `world_data.json` (`labels`) | Static `mapTextItems` with other marker types |
| Region outlines | `world_data.json` (`points`, `areas[name].points`) | Drawn by hand (or generated, see below) |
| Background image | `assets/maps/color/{name}.webp` and `.png`, same for `classic/` | `Images/Maps/Map{Name}Hex.TGA` in the War API repository, 1024 × 888 like ours |

File names are the hex name in lower case without `Hex` (`kingscage.webp`), as built in
`map/hex/background.svelte`. Note the odd one out in the API: `MarbanHollow` has no `Hex`
suffix.

## The existing 37 are out of date too

Comparing `world_data.json` with today's static data:

- 12 hexes have different regions: 21 region names are new and 26 are gone. Godcrofts and
  Oarbreaker changed most (6 and 5 new regions), then Endless Shore, Fishermans Row, Farranac
  Coast, Tempest Island, The Fingers, and Morgens Crossing.
- Two are only spelling fixes: "Hangmen's Court" is now "Hangman's Court", "GoldenRoot
  Ranch" is now "Goldenroot Ranch".
- 29 minor labels are new and 41 are gone.
- The 2022 background images predate these terrain changes as well.

Region outlines are used to colour a region by the team holding its town or relic base, so
in the changed hexes some regions are now coloured wrongly or not at all.

## Grid positions

The War API has no layout data, and `BGOneWorldMap.TGA` in the API repository is a
decorative background, not a grid. Positions must come from the in-game world map, or a
community map such as the [Foxhole Wiki](https://foxhole.wiki.gg/) or
[LogiWaze](https://www.logiwaze.com/).

The current grid is a flat-topped staggered layout: `col` 0–6, `row` 0–12, where a step of
one row is half a hex height (`grid.js`: hex 1024 × 888, `column_factor` 1.333,
`row_factor` 2). Dead Lands, the centre, is at col 3, row 6. The original 37 form a
hexagon of radius 3 around it; the 16 new hexes sit on the next ring, which is only partly
filled (a full ring would be 24).

The new ring needs columns −1 and 7 and rows −2 to 14. Rather than allowing negative
values, shift every existing hex by +1 column and +2 rows, so positions stay 0-based and
`grid.js` needs no change. The total map size grows from 7 × 13 to 9 × 17 positions; check
that the initial "fit to screen" in `panzoom.svelte` still looks right. Saved views in
`localStorage` (`pzt`) will point at the wrong place after the shift: rename the key, for
example to `pzt2`, so everyone starts centred once.

## Region outlines

Today's method is the dev-only points tool (`tools.points` in `config.js`): click on a hex
to place lettered points, then list point letters per region. It is accurate but slow:
roughly 4–10 points per region, 111 new regions, plus the 12 changed hexes.

Faster option, worth trying first: generate a starting point automatically.

1. For each hex, take the major label positions from the static data as region centres.
2. Compute a Voronoi diagram of those points, clipped to the hexagon outline.
3. Write the cells out in the same `points` / `areas` format `world_data.json` already
   uses, with the hexagon corners named `nw`, `ne`, `ee`, `se`, `sw`, `ww` as 16 of the
   existing hexes already do.
4. Correct the cells that do not follow the in-game borders with the points tool.

Foxhole's region borders are not exactly Voronoi cells, so step 4 is still needed, but it
turns drawing 111 shapes from scratch into adjusting them. A small Node script in
`.app/scripts/` can do steps 1–3; it is a one-off tool, so it does not need to ship in the
app.

## Images

The official `Map{Name}Hex.TGA` images match the in-game look today. Our `color` set (the one
in use, `map_type` in `config.js`) has a different, recoloured style (orange roads), so new
official images next to the old ones would look mismatched.

Options:

1. **Replace all 53 with the official images** (recommended). Consistent, and the 37 old
   ones are outdated anyway. Drop the `color` set or keep it as an optional style for the
   37 hexes only.
2. Recolour the official images to match `color`. Only worth it if the orange-road style is
   important; it needs a colour mapping per terrain type.

Conversion uses the same tooling as the icons (decode the TGA, write `.webp` and `.png`),
which can live in the same one-off script.

## Order of work

1. Write the one-off script: download the static data and TGA images for all 53 hexes,
   convert the images, and generate `id`, `title`, `areas` with label positions, `labels`,
   and Voronoi outlines.
2. Collect the grid positions of the 16 new hexes, shift the existing positions, and add
   them.
3. Regenerate the 12 changed hexes the same way, keeping the hand-drawn outlines of
   regions that did not change.
4. Review each hex with the points tool and correct outlines that are clearly off.
5. Rename the saved-view key, check the initial fit, and check the summary and dynamic
   layers on the new hexes (icons should appear as soon as the hex exists).
6. Update the search plan's counts, since search reads the same data.

- Each region contains at most one town or relic base, and every town and relic base falls
  inside exactly one region (the same point-in-polygon test the areas layer uses).
- Screenshots of the full map zoomed out and of one new hex zoomed in.

## Result

Done with `.app/scripts/build-hexes.js`, which can be run again after a Foxhole update.

- **Grid positions** come from [notbadjon/foxhole-hexes](https://github.com/notbadjon/foxhole-hexes)
  (MIT), whose axial coordinates map onto our grid as `col = p + 6`, `row = p + 2q + 6`. That
  formula reproduces 29 of the 37 old positions exactly. The other 8 (Tempest Island, Endless
  Shore, Westgate, Godcrofts, Fishermans Row, Farranac Coast, The Fingers, Oarbreaker) really
  moved: Foxhole rearranged the edges of the world when it added hexes. The world is now 13
  columns wide instead of 7, so no "+1 column" shift was needed, only +3.
- **Outlines:** 26 hexes kept their hand-drawn outlines (a spelling change such as
  "GoldenRoot Ranch" still matches). 11 changed hexes and the 16 new ones have generated
  Voronoi outlines, to be refined with the points tool where they look wrong.
- **Images:** all 53 `classic` backgrounds are now the official War API images, and `classic`
  is the default map style. `color` keeps its 37 recoloured 2022 images and falls back to
  `classic` for the rest.
- The saved view moved from the `pzt` to the `fatt-view` localStorage key, and the minimum
  zoom went from 0.1 to 0.03 so the wider world fits on a phone.
